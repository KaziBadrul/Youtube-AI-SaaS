# S8 — Backup, restore and deletion safety

**Verdict: PASS — local protocol proof, with off-host/operational limits.** [Raw evidence](S8.json).

**Claim:** consistent SQLite/media snapshots, authenticated encryption, independently recoverable non-content deletion authority and fail-closed reconciliation can satisfy the accepted seven-day/live and next-day/backup deletion procedure and structurally support daily catastrophic recovery.

**Failure sought:** inconsistent DB/media, plaintext/tampered backup accepted, restored spending capacity ignoring real charges, ambiguous execution resumed, incomplete deletion authority, older-snapshot resurrection, or backup failure extending purge deadlines.

**Experiment / criteria:** [predeclared S8 plan](PLAN.md#s8). SQLite backup API while another connection persists 80 progress events; media/spool hash manifest under snapshot/destructive-maintenance exclusion; AES-256-GCM random nonces and a separately held test key. Restore into empty storage. An independent authenticated deletion event journal and latest-head receipt survive separately from database snapshots. Controlled seconds simulate seven days and ≤24-hour daily cycles; no real wait/storage purchase. All invariants must pass; overdue snapshot age is a failed recovery target, never a hidden PASS.

**Command:** `/tmp/alpha-feasibility-venv/bin/python spikes/local-feasibility/s8.py`.

**Observed:** five-file initial manifest restored DB, referenced private media/spool, project/scene/artifact/attempt/ledger/account state with matching hashes. Concurrent progress writes did not corrupt the snapshot. Tampered and partial ciphertext failed authentication. Running/uncertain jobs became recovery-required and the lane stayed blocked; admission was denied until reconciliation. Known post-snapshot external spending **and consumed allowance** were reconciled before admission, preventing backup rollback from recreating capacity. Unknown liability continued to block paid work.

Deletion intent was durably recorded before database acknowledgement; a process exit at that boundary left private access denied through independent authority. Recovery applies pending intents and cancels never-started queued work before worker claims. Restoration succeeded immediately before seven days and was denied exactly at the deadline. Live purge removed scene/artifact/media/spool content and retained only non-content accounting/deletion identity. The next cycle removed old recoverable content snapshots at the 24-hour boundary **even when creation of the new backup failed**. Interrupted ciphertext was removed independently of replacement success. A deliberately retained older snapshot restored into another empty directory had purge authority reapplied before access and could not resurrect private content. The other project stayed available.

Missing/corrupt journal failed closed; replacing it with an older valid authenticated journal failed against the independently current head. Restore also rejects authority behind a snapshot's cutoff. A snapshot older than 24 hours was explicitly reported outside the RPO and left paid work blocked. Failed backup retained the last valid snapshot rather than publishing partial success.

**Failures / limits:** no final invariant failure. This is a temporary **local** destination modeling off-host storage, not proof of geographic or failure-domain independence, backup-provider historical-copy purge, key custody, scheduler reliability, full-volume throughput or monthly cost. The journal and its latest head must be recovered from their own current independent authority; rolling back/losing that whole authority is not solved by these local files and must fail closed. Production must coordinate destructive maintenance and gate startup/access/claims while intents are unresolved. Daily monitoring must detect missed/overdue backups; an outage cannot guarantee a 24-hour RPO. Fake external financial totals are not actual billing reconciliation (S4).

**Consequence:** the accepted backup/deletion model is structurally credible; no requirement or deadline was changed. Actual off-host persistence, key recovery, inaccessible historical copies and full storage/traffic economics remain S9/operational evidence. The local AES/journal witness does not select a vendor or production backup implementation.
