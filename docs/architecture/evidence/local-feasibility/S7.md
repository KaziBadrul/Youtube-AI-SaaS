# S7 — Publication and restoration crash safety

**Verdict: PASS — structural publication/restoration invariants.** [Raw evidence](S7.json).

**Claim:** staged response → validated bytes → immutable durable installation → transactional metadata/financial registration → guarded current selection can recover without falsely treating filesystem and database as one transaction.

**Failure sought:** incomplete/orphan files displayed as success, invalid replacement erasing a good export, double settlement, stale shared-segment selection, or restoration changing words/configuration/siblings without approval.

**Experiment / criteria:** [predeclared S7 plan](PLAN.md#s7). Three repeats at nine boundaries: response, stage, validation, install, **inside metadata/ledger transaction**, committed metadata, committed finance, selected and final export published. Old synthetic export remains downloadable; unregistered bytes cannot select. Recovered output reused exactly once; invalid files denied; compound/scoped restoration preserves historical provenance/manual work and siblings.

**Command:** `/tmp/alpha-feasibility-venv/bin/python spikes/local-feasibility/s7.py`.

**Fixtures:** private immutable synthetic export bytes; valid 8,000-frame silent WAV with a decoded 0–4,000-frame source range; recorded words/voice/delivery; explicit pinned shared members; compatible local timing/caption bundle and manual-version dependency fixtures. These are not a speech-quality or MP4 fixture.

**Observed:** all 27 crash cases passed. Prior export remained selected until replacement selection; its bytes remained available after replacement. Exit inside registration rolled back artifact and delivery ledger together. Staged/installed unregistered output never became current. Recovery/replayed recovery used one fake submission and one financial event. Missing/corrupt installation was rejected, retained the previous export and recovered from existing paid bytes.

Changing either pinned member of the shared response made the entire arriving branch history-only, without selecting sibling ranges. Editing the other private project did not veto a compatible result. Single-scene restoration decoded/validated the historical range; matching words with different recorded voice/delivery required approval, adopted configuration only for that scene, and preserved the sibling. Different words required compound approval before changing text/audio. Compatible local timing/caption references were restored; no compatible bundle left timing/captions missing/outdated. Incompatible manual versions remained preserved and explicitly outdated; independently matching manual dependencies remained compatible. Source provenance stayed immutable and restore incurred no generation charge.

**Failures:** no final invariant failure. Selection verifies installed hashes before its short fenced/CAS transaction; malformed/missing bytes cannot bypass registration. Restoration checks were tightened to require an explicit compatible bundle rather than manufacture timing/caption references, and manual compatibility is tied to preserved dependencies rather than current text alone.

**Limitations:** synthetic export proves crash/selection semantics, not MP4 validity, FFmpeg/caption correctness or S6 resources. Silent WAV range extraction proves storage/provenance structure, not audible joins, approved-word alignment or a viable narration strategy: those remain S5. Fixture compatibility envelopes are deliberately small; production derived script/assembly/signatures need implementation tests. Process exit/fsync tests are not a controller/power-loss test on the future host.

**Consequence:** retain private immutable media plus durable registration and separately guarded selection. Historical single-scene ranges/restoration are structurally representable; narration granularity and actual safe joins remain conditional. No global segment restore or sibling text/configuration change was silently introduced.
