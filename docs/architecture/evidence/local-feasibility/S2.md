# S2 — SQLite concurrency and transactional safety

**Verdict: PASS — documented single-host candidate at fixture load.** [Raw evidence](S2.json).

**Claim / failure sought:** local WAL SQLite, foreign keys, FULL synchronous durability, 5-second busy timeout and short `BEGIN IMMEDIATE`/CAS transactions can prevent double reservation/claim/charge, lost accepted edits, invalid selection, deleted-project launch, stale completion and leaked render locks. Integer monetary units only; no provider/media delay in a transaction.

**Minimum experiment / criteria:** [predeclared S2 plan](PLAN.md#s2). Independent connections in eight simultaneous processes, 20 repeats of each of eight race families (160 rounds / 1,280 actors); then eight writers × 100 persisted events. All invariants, integrity and foreign keys must hold, no unhandled lock failure; fixture stress max <5 seconds and p99 <2 seconds. These are experiment evaluation thresholds, not a product SLA. Failure of fundamental guarantees would require explicit PostgreSQL reconsideration.

**Command:** `/tmp/alpha-feasibility-venv/bin/python spikes/local-feasibility/s2.py`.

**Fixtures:** two private projects, versioned scene edits, singleton production lane, integer cap/allowance, queued jobs, local registered WAV, selections and event ledger. Real processes race autosave, duplicate/capacity admission, claims, registration, deletion vs claim, render lock vs edit and cancellation vs selection. Forced process exit inside reservation/render-lock/edit transactions checks rollback. Additional assertions reject stale input/fence and cross-project selection.

**Observed:** all 160 rounds and 800 contended writes passed with no lost accepted event, duplicate claim/reservation/delivery or integrity/foreign-key failure. Final contention p99 **0.0104 s**, max **0.1361 s**; largest race operation **0.0860 s**. Expected edit conflicts, blocked admission and rejected deletion remain explicit. Interrupted multi-record mutations rolled back; render locks are held/released consistently. No network or media execution was held inside a write transaction.

**Failure retained:** [first run](S2-first-run.json) incorrectly classified a second deletion's expected `PermissionError` as an infrastructure failure. The harness now labels it `already_deleted_denied`; the deletion/claim invariant and Store behavior were not relaxed. Final matrix was rerun.

**Limitations:** tiny fixtures, eight actors and this workstation only; no arbitrary future scale, multi-host WAL, full production ORM schema, disk-full controller fault or production latency promise. Exact contention depends on transaction size and target disk. Production must use real exclusion/CAS; `select_for_update` cannot supply SQLite row locks.

**Consequence:** retain the conditional local SQLite recommendation for one persistent host. No measured fundamental failure triggers PostgreSQL migration. Reconsider if topology/load or later implementation violates these bounds/invariants.
