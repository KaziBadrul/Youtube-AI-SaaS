## Integration contradictions and filesystem assumptions

1. TTS writes WAV and alignment reads WAV, but primary rendering reads `narration.mp3` (`make_video:480`). The alternate renderer reads WAV.
2. TTS derives from humanized/voice-tagged text; alignment derives from scene narration. No equality validation connects them.
3. Image generation writes JPG; alignment/render defaults refer to numbered PNGs. No conversion contract was found.
4. Source-relative paths, interactive choices, fixed filenames, import/startup client initialization and mutable globals prevent direct safe use as unattended multi-project workers.
5. Filename existence is not input compatibility. Restore/resume can silently reuse wrong content; output overwrites destroy prior selections.
6. Raw exceptions and stdout are not durable, secret-safe job histories. No credentials were read during this audit.

## FFmpeg execution and recovery evidence

Both renderers use blocking `subprocess.run`. There is no child-process identity, structured progress, timeout, cooperative cancellation, termination escalation, worker lease or persisted render lock. Failures can leave intermediates, but rerun overwrites/rebuilds them; it is not deterministic checkpoint recovery. CPU/RAM, scratch-space peak and render duration have not been measured.

FFmpeg provides machine-readable `-progress` output suitable for a controlled subprocess boundary; see [official FFmpeg documentation](https://www.ffmpeg.org/ffmpeg.html). Cancellation and crash recovery remain architecture requirements rather than existing behavior.

## Reuse conclusion

Provider calls, prompt construction, narration preparation, alignment ideas, SRT formatting and FFmpeg command construction are candidates for reuse. Current entry points are not safe web workers. The principal obstacles are uncontrolled orchestration/cost, file-based identity, narration granularity, nonvalidated outputs and missing durable state—not Python itself. Subsequent discovery A10 selected Python reuse behind a controlled worker rather than a language-consistency rewrite, contingent on validation.
